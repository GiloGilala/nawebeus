# Migrations (NWB-P0-005)

`drizzle/migrations/` is the committed, ordered history of the **active** schema
(the tables re-exported by `db/schema.ts`). Generated by `bun run db:generate`;
applied by `bun run db:migrate` (idempotent — a second run against the same
database is a no-op, tracked in the `drizzle.__drizzle_migrations` ledger table).

Rules of the road:

- **Evolve through migrations, not push.** Change the schema in `db/**`, run
  `bun run db:generate`, review the generated SQL, commit it with the change,
  and apply with `bun run db:migrate`. CI's test job runs `db:migrate` twice —
  once to build the database, once to prove the no-op guarantee.
- **`db:push` stays for dev convenience** (throwaway local databases). It now
  *converges* — the 42P16 class died when every `primaryKey()` gained
  `.notNull()` (NWB-P0-009) — but each run still unconditionally
  `DROP ... IF EXISTS` + `CREATE ... IF NOT EXISTS`-es **36 indexes** that carry
  `DESC` ordering and/or partial `WHERE` clauses (a drizzle-kit introspection
  gap on PG14; deterministic, safe, and it is why push is not the evolution
  path).
- **pg-boss is library-managed.** When the Phase 2 queue lands
  (NWB-P0-002's async half and friends), `pgBoss.start()` creates and versions
  its own tables on process start. Those tables must NOT enter this directory —
  drizzle knows nothing about them and must never try to.
- **ADR-017 renames** live in `db/manual-migrations/campaign-domain-disambiguation.sql`.
  They apply only when the (aspirational, schema-excluded) PR/influencer modules
  are adopted — fold them into the first migration that module adoption
  generates rather than running the file by hand.
